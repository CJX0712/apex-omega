# APEX-Ω · 门禁规格

> **尺子照出的不是胜利，是洞。**
> 作者：晨星 · MIT

---

## 〇、两类门禁，缺一不可

| 类别 | 验证对象 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **甲类 · 内部不变量** | 旗舰的算子层 | 「旗舰的算子是对的」 | 证明不了旗舰与世界顶级实现接得上 |
| **乙类 · 对外对拍** | 旗舰 vs llama.cpp | 「旗舰与世界顶级引擎接得对」 | 不覆盖旗舰自身的全部数学正确性 |

**只有甲类** → 是自说自话（自己证明自己没写错）。
**只有乙类** → 尺子太窄（接得上但内部可能错）。
**两类齐备** → 旗舰才有资格说「世界顶级」。

## 一、甲类门禁（ISA 组，11 项）

全部来自 AXIOM 的 1024 条微指令注册表与其 386 项数学不变量，**零改动复用**。
**本组不需要模型**，可在 CI / 离线 / 无 GPU 环境完整复现。

| # | 门禁 | 判据 | 为什么这样定 |
|---|---|---|---|
| A1 | 指令总数 | = 1024 | 上游规格 |
| A2 | ID 唯一 | 无重复 | 注册表基本完整性 |
| A3 | 每族条数 | 每族恰 64 条 | 16 族 × 64 |
| A4 | **每 (族,算子) 变体数** | 恰 4 变体 | **不是**「每 op 4 变体」—— 上游有 13 个 op 跨族复用（见下） |
| A5 | 跨族同名 op 识别 | 恰 13 个 | 固化上游设计，防止未来的误改 |
| A6 | 变体取值域 | ⊆ {base, batched, fused, inplace} | 上游规格 |
| A7 | 全部含数学不变量 | 非空字符串 | 「可枚举的正确性」的前提 |
| A8 | verified 项实现真实存在 | `core.cjs` 有对应导出 | 防止注册表指向不存在的实现 |
| A9 | **AXIOM 数学不变量全量** | 386/386 全绿 | 上游权威自检 `runChecks()` |
| A10 | **参照采样器分布自检** | 最差 TVD ≤ 0.03 | 旗舰原创：已知分布上采 20000 个样本，经验频率须收敛到理论值 |
| A11 | （甲类合计） | 11/11 | 其中 A10 曾在开发中抓到「批量采样器被当单值用」的回归 |

### A10 的性能陷阱（实测）

AXIOM 的 `categoricalSample(p, seed)` 一次调用即返回 **20000 个 iid 样本**。
第一版自检按「一次调用取一个样本」循环 20000 次 → **56 秒同步阻塞**。
修正为「一次调用取整批」后降到 **~1ms**（20000× 加速）。
教训：**复用上游算子前，先读它的返回形状**。

### 关于 A4 的诚实说明

上游注册表中 **13 个 op 名跨族复用**（`softmax` `sigmoid` `gelu` `relu` `flatten` `trace` `seed_repro` `marginal` `condition` `perplexity` `grad_clip` `self_attn` `map`），每个出现 **8 次**而非 4 次（因为它们同属两个族）。

旗舰最初的断言「每 op 恰 4 变体」**会误报失败**。修正后的断言是「每 **(族, 算子)** 恰 4 变体」—— 尊重上游设计，而非强加自己的假设。

**路由同理**：旗舰的 `IsaRouter` 按 **impl 名**（`core.cjs` 的真实导出名）定位指令，而非 op 名。op 名会歧义，impl 名不会。

## 二、乙类门禁（对拍组，4 项）

### B1 · chat wrapper 语义健康

| 项 | 值 |
|---|---|
| 判据 | 输出非退化（字符多样性 ≥ 0.2），非空 |
| 对手 | 「模型坏了」这个假设 |
| 抓的真实坑 | Qwen2.5-Instruct-GGUF 若未套用 `QwenChatWrapper`，输出退化为 `!!!!` |

这条门禁的存在意义：**它把一个「看起来像模型坏了」的现象，定位成了「协议套用错误」**。没有这条门禁，开发者会怀疑模型、怀疑量化、怀疑硬件。

### B2 · 贪心解码逐 token 一致

| 项 | 值 |
|---|---|
| 判据 | 两次**独立 context** 的贪心输出，token 序列逐 token 相同 |
| 对手 | 推理内核的非确定性 |
| 关键技术 | `isolate: true` —— 复用 sequence 会带入上一轮 KV cache |

### B3 · 同 seed 可复现

| 项 | 值 |
|---|---|
| 判据 | 同 seed、同 prompt、两次独立生成，逐 token 相同 |
| 对手 | 采样器的种子语义缺失 |
| 关键技术 | 同上，`isolate` + `tokenId()` 归一化 |

### B4 · 真·分布对拍（核心门禁）

**这是旗舰的技术核心。**

#### 要解决的问题

llama.cpp 不暴露内部 logits。想验证「旗舰的 ISA 参照采样器与 llama.cpp 的生产采样内核语义一致」，常规做法是拿自造的代理分布去比 —— 那是**自说自话**，毫无判别力。

#### 三步逼近（全部为本机实测）

**第一步 · 探明 TokenBias 语义**

`TokenBias.set(tok, {logit: X})` 的源码确认是绝对值赋值（`_biases.set(token, resolvedLogit)`）。但实测：

```
只钉部分候选为 logit=3.0    → 仍选模型原始 argmax（未生效）
全表钉定（其余 token = -100） → 精确选出期望 token ✅
```

**第二步 · 判定 bias 的叠加性**

固定候选间的 bias 差 Δ ∈ {0, 1, 3, 8, 20}，实测分布**纹丝不动**（始终 39/40 集中在第一个）：

> 结论：`logit_bias` 是**加性**的 —— 有效 logit = 原始 logit + bias。

**第三步 · 二分反推原始 logits**

加性 ⇒ 「翻转临界点」直接给出真实 logit 差：

```
给候选 j 施加 bias b，找 winner 从 cand0 翻到 cand_j 的临界 b*
  ⇒ b* = orig_0 − orig_j        记作 gaps[j]
  ⇒ 实测示例：orig_0 − orig_1 = 5.2918
```

#### 构造完全已知的分布

```
施加 bias[j] = TARGET[j] + gaps[j]
有效 logit[j] = orig_j + TARGET[j] + gaps[j]
             = (orig_0 − gaps[j]) + TARGET[j] + gaps[j]
             = orig_0 + TARGET[j]        ← 完全已知！
```

于是两侧跑在**同一已知分布**上：

| 侧 | 实现 | 方法 |
|---|---|---|
| 甲 | llama.cpp GGML 生产采样内核 | `generateCompletion` + `tokenBias` |
| 乙 | 旗舰 ISA 参照采样器 | AXIOM `softmax`/`topK`/`topP`/`categoricalSample` |

| 项 | 值 |
|---|---|
| 判据 | `TVD(p, q) ≤ 0.35`（N=60 时双样本噪声的经验上界） |
| 辅助指标 | JS 散度 |
| 为什么有判别力 | 两侧在**同一已知分布**上，残差只反映采样噪声；若采样语义理解有误，TVD 会立刻爆掉 |

#### 实测数据（2026-10-24）

```
旗舰 ISA 参照（理论）:  0.6439  0.2369  0.0871  0.0321
llama.cpp（实测）    :  0.6333  0.2833  0.0667  0.0000
✅ TVD=0.0583 ≤ 0.35 · JS=0.0138 · 反推 logit 差 [0.00, 2.08, 4.81, 5.81]
```

#### 一个被尺子抓到的符号错误

旗舰首版把 bias 写成 `TARGET[j] − gaps[j]`，导致 `orig_j` 被**重复计入**（有效 logit = `orig_0 + TARGET − 2·gaps`），分布被压成 120/120 集中在一个 token 上。

**若没有这条门禁，这个 bug 会静默通过**（因为阈值 `<= 1.0` 恰好能过 —— 这本身是一个假绿）。修正为 `TARGET[j] + gaps[j]` 后，分布与理论值吻合。

#### 一个被尺子抓到的「假失败」

首版 TVD 恒等于 **0.4917**，而手算 `observed` 与 `theory` 的真实 TVD 只有 0.055。
对不上 → 反推出参照侧经验分布恒为空数组 → 根因是 `categoricalSample` 返回 **20000 个样本的数组**，被当成单个索引用。

**教训**：门禁报 FAIL 时，先证明「尺子是对的」，再判定「对象是错的」。

> 这是「尺子」最典型的价值：**它照出的不是胜利，是洞。** 而如果没有尺子，洞就是沉默的。

## 三、运行

```bash
npm test                      # 全量门禁
node test/run.js --rounds 200 # 更密的采样（更慢，判据不变）
node test/run.js --json       # 机器可读输出
```

退出码：`0` = 全绿，`1` = 有失败。

## 四、门禁的诚实边界

| 边界 | 说明 |
|---|---|
| B4 在**构造分布**上对拍 | 因为 llama.cpp 不暴露 logits。B4 验证的是**采样语义**（温度/topK/topP/分布采样）的一致性，不是模型内部数值本身。B2/B3 覆盖后者。 |
| B4 的采样噪声 | N=60 时 TVD 有约 ±0.1 的自然波动，故判据取 0.35 而非 0。 |
| A9 复用上游自检 | AXIOM 的 386 项由上游 `runChecks()` 执行，旗舰不重复实现（零重写）。 |
| 无 GPU 路径 | 本机实测为 CPU（`gpu: false`）。Vulkan 路径存在但未纳入门禁基线。 |
| 模型相关门禁需模型 | B1–B4 需本地 GGUF；缺失时门禁记为 `skipped` 并明确标注，**不冒充通过**。 |
